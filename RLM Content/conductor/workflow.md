# Workflow Preferences

The project's workflow is organized around a content-centric, date-based system.

## Content Development

1.  **Core Concepts & Structure:** Foundational ideas, outlines, and strategic documents are developed in the `Book Development/` directory. These files define the overall architecture of the "PAUSE" system and the book.

2.  **Atomic Content Creation:** Individual pieces of content (stories, exercises, philosophical points) are created as individual Markdown files within the `Content Database/` directory.

3.  **Categorization:** Content is organized into subdirectories within `Content Database/` that correspond to the "buckets" defined in the project's knowledge map (e.g., `1-Core-Exercises`, `2-Library-Philosophy`, etc.).

4.  **Naming Convention:** All content files in the `Content Database/` follow a strict `YYYY-MM-DD-title.md` naming convention. This likely corresponds to the date the content was created, published, or intended for use.

## Review and Integration

There is no formal, automated code review or CI/CD process, as the project is content-based. The workflow is manual and file-based. Integration of the individual content pieces into the final book manuscript is a manual process based on the outlines in the `Book Development/` directory.
